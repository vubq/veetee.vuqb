# M3 implementation note

## UDP v3 framing/crypto/reorder core — host-only (2026-08-05)

Đã triển khai phần lõi carrier theo `docs/03-protocol-spec.md` mà không mở MQTT
broker, UDP socket, network route hay audio device. Module
`veetee-server/src/veetee_server/mqtt_udp.py` có ranh giới rõ:

- parse server hello `transport="udp"`, key/nonce 16-byte và optional audio
  parameters; key/nonce không được log;
- serialize/validate header UDP v3 16 byte (`type`, `flags`, `payload_len`,
  `ssrc`, `timestamp`, `sequence`) và AES-128/CTR dùng toàn bộ header làm IV;
- sequence bắt đầu từ `1`, chặn payload trên 1.400 byte và từ chối wrap trước
  khi reuse IV;
- bounded reorder window 4 packet, forward jump tối đa 256, gap timeout 120 ms,
  duplicate/late drop và reset state khi protocol error.

Golden vector dùng key/nonce giả lập được lưu tại
`tests/fixtures/mqtt_udp_v3.json`; không chứa credential thật, raw audio hay
secret. Test `veetee-server/tests/test_mqtt_udp.py` chỉ dùng payload byte nhỏ để
kiểm tra framing/crypto, không phát hoặc mở microphone/speaker.

Verification:

- `uv run pytest -q`: **91 passed** (82 regression hiện có + 9 UDP core);
- `uv run ruff check src tests`: pass;
- `uv run python -m compileall -q src`: pass.

Đây chưa phải M3 DoD. MQTT control client, UDP gateway/socket, stream barrier
`tts/start`/`tts/stop`, loss/reorder soak, firmware transport, hardware MCP,
assets/OTA và physical acceptance vẫn deferred. Không được promote MQTT/UDP làm
default; direct WebSocket v3 vẫn là product default.

## Ordering barrier giữa MQTT control và UDP audio — host-only (2026-08-05)

Đã thêm `UdpTtsStreamBarrier` (cùng các alias `UdpStreamBarrier` và
`UdpTtsStreamCoordinator`) vào cùng module. Primitive này chỉ nhận
`UdpAudioPacket` đã được carrier giải mã và trả về packet được phép đưa sang
decoder; nó không mở MQTT/UDP socket, không decode Opus và không phát/thu âm.

- Packet đến trước `tts/start` được buffer theo `audio_stream_id`, tối đa 8
  packet/480 ms; overflow hoặc timeout mark stream invalid và xóa pending.
- `tts/start` kiểm tra session/stream/sequence, áp dụng `start_sequence - 1`
  vào reorder receiver, khai báo prefix unresolved là lost và chỉ release từ
  boundary inclusive. Packet pre-start dưới boundary, quá xa hoặc sai stream
  bị drop.
- `tts/stop` chuyển stream sang `DRAINING`; packet sau `end_sequence` bị drop,
  chỉ hoàn tất khi đúng end sequence đã release. Sau 1.200 ms chưa drain xong,
  primitive mute/flush bằng cách clear state, đánh dấu abort/timeout và không
  cho packet cũ đi tiếp.
- `abort`, `reset` và `key_rotation` xóa active/pre-start/expired state cùng
  reorder slots trước generation mới. Counters barrier được giữ ở
  `UdpStreamMetrics` để gateway sau này map sang telemetry.

Verification host-only:

- `uv run pytest -q`: **99 passed** (82 regression + 17 UDP framing/reorder/
  barrier tests).
- `uv run ruff check src tests`: pass.
- `uv run python -m compileall -q src`: pass.
- Không restart runtime, không mở socket/route, không dùng database, không
  chạy microphone/speaker, không flash/reset ESP32.

Đây vẫn chưa phải M3 DoD: MQTT client/gateway, UDP socket, firmware carrier,
loss/reorder soak, hardware MCP, assets/OTA và transport-promotion evidence còn
mở. WebSocket v3 vẫn là default và không có silent transport fallback.

## MQTT control boundary — host-only (2026-08-05)

Đã thêm `veetee_server.mqtt_control` làm boundary thuần dữ liệu cho phần MQTT
control của profile `mqtt-udp-v3`. Module không tạo MQTT client/broker, không mở
socket và không thực hiện DNS/network operation.

- `parse_mqtt_session_config()` validate endpoint host/port (default 8883),
  client ID, opaque exact `publish_topic`/`subscribe_topic`, keepalive, QoS và
  bắt buộc `retain=false`; credential chỉ tồn tại trong object với `repr` ẩn và
  `redacted()` chỉ trả cờ có/không.
- `encode_control_payload()`/`decode_control_payload()` enforce đúng một JSON
  object UTF-8, ceiling 8.192 byte, finite number và safe integer range; unknown
  field được giữ nguyên, unknown downstream type được ignore.
- Client/server hello được validate riêng; server hello dùng lại validator UDP
  v3 để không tạo hai bộ luật key/nonce/audio khác nhau.
- `MqttControlChannel` chỉ tạo publish request với topic/QoS config và chỉ nhận
  subscribe topic chính xác, session hiện tại chính xác; đây là adapter input
  cho MQTT client tương lai, chưa được nối vào Voice runtime.
- Golden fixture bổ sung tại `tests/fixtures/mqtt_control_v3.json`; không chứa
  credential thật, raw audio hay secret.

Verification targeted: `uv run pytest -q tests/test_mqtt_control.py` **20

## Deterministic loss/reorder soak — host-only (2026-08-05)

Bổ sung `tests/test_mqtt_udp_soak.py` để chạy transport core bằng packet bytes
giả lập, không dùng raw audio, MQTT broker hay UDP socket. Soak dùng seed cố
định, permute trong nhóm tối đa bốn packet, kiểm tra profile mất `0%`, `1%`,
`5%`, duplicate/reorder và stream tuần tự 20.000 packet.

Trong khi chạy soak, reorder core cũng được harden: không tuyên bố một sequence
đã có trong slot là lost khi cửa sổ tiến lên, và `reorder_slots` luôn giữ tối đa
4 packet ngay cả khi có nhiều gap rời rạc. Packet cuối được giữ trong fixture để
kiểm tra graceful `end_sequence`; trường hợp mất packet cuối vẫn được kiểm tra
riêng bằng stop-timeout barrier.

Verification: `uv run pytest -q tests/test_mqtt_udp.py
tests/test_mqtt_udp_soak.py` **22 passed**; full Voice Server suite sau thay đổi
**124 passed**, Ruff và compileall pass. Đây là evidence host-only; chưa mở
carrier thật và chưa đủ để promote MQTT/UDP hoặc đóng M3.

## MQTT/UDP session coordinator — host-only (2026-08-05)

Đã thêm `veetee_server.mqtt_session.MqttUdpSession` để ghép các primitive thành
state machine testable: `NEW → HELLO_SENT → READY → CLOSED`. Coordinator validate
client hello v3, import server hello key/nonce, tạo `MqttControlChannel` và
`UdpTtsStreamBarrier`, route control có ordering fields, decrypt datagram qua
`UdpCryptoSession`, và clear generation/key material khi abort/goodbye/close.

Lớp này chỉ trả `MqttPublish`, `MqttSessionEvent` hoặc `UdpStreamResult` cho carrier
tương lai; không kết nối broker, không tạo UDP socket, không gọi Opus decoder,
không phát/thu audio và không tự fallback sang WebSocket.

- Test `tests/test_mqtt_session.py`: **5 passed**, gồm explicit v3 handshake,
  server hello routing, encrypted datagram → barrier, abort/goodbye cleanup và
  malformed pre-ready control.
- Full Voice Server suite sau coordinator: **133 passed**, Ruff và compileall
  pass.

Coordinator là composition boundary, chưa phải live gateway hoặc transport
promotion. MQTT client, UDP socket/firmware carrier, real-network loss/latency,

## UDP sequence guard parity — host-only (2026-08-05)

Hardening nhỏ để hai peer dùng cùng invariant: `UdpCryptoSession.decrypt()` giờ
từ chối datagram có sequence `0` ngay sau khi kiểm tra length, trước khi giải mã
hoặc đưa packet vào stream barrier. Firmware clear-header codec vốn đã từ chối
sequence `0`; trước thay đổi host crypto layer còn trả packet rồi mới bị barrier
drop.

- Regression mới `test_udp_crypto_rejects_zero_sequence_before_barrier` kiểm tra
  lỗi `UDP_SEQUENCE_INVALID`.
- Voice Server targeted UDP: **18 passed**; full suite sau hardening: **134
  passed**, Ruff và compileall pass.
- Không mở carrier/socket/broker, không decode/play audio và không tác động
  firmware/network/database; WebSocket v3 vẫn là default.

## Firmware MCP registry core — host/ESP-IDF build-only (2026-08-05)

Đã thêm `veetee-firmware/main/veetee_mcp.[ch]` làm core registry bounded, tách
khỏi cJSON, FreeRTOS và HAL để có thể test độc lập. Caller cung cấp descriptor
manifest và callback owner task; core không nhúng tên tool, GPIO, broker/topic
hay localized text.

- Giới hạn: tối đa 16 descriptor và cache 16 completed calls, result mỗi call
  tối đa 768 byte; tool name tối đa 63 byte.
- Enforce positive signed-32-bit request ID, monotonic high-water, duplicate
  digest, `duplicate_conflict`, `duplicate_expired`, cache hit và reset theo
  session. Cache dùng digest length-prefix fixed-width để không phụ thuộc
  endian/word-size giữa host và ESP32.
- `mcp_registry` host CTest mới cover descriptor uniqueness, empty registry,
  invoke/cached duplicate, conflicting ID, eviction/reset, unknown tool và
  oversized result. Firmware host CTest tổng: **3/3 passed**.
- ESP-IDF 6.0.2 build sau module: **9/9**, binary `0x1593e0`, app partition còn
  **66%**. Đây là registry/dispatch core; JSON-RPC envelope, cJSON parser,

- Không flash/reset/erase, không mở carrier/audio/network side effect và không
