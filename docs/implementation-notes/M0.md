# M0 implementation note

> Trạng thái: host + board/network gate đã pass; physical speaker acceptance vẫn
> cần người dùng xác nhận nghe được âm thanh từ loa.

## Scope

Vertical slice tối thiểu là PTT → Opus → direct WebSocket v3 → VAD/ASR → Groq
stream → VieNeu stream → Opus → speaker. Các service control-plane vẫn được
khởi động và health-check trong cùng runtime harness nhưng không nằm trong critical
audio path.

## Config and safety

- Config đọc từ environment/manifest fixture; không hard-code model, provider,
  endpoint, credential, personality, prompt hoặc GPIO.
- `secrets/groq.keys` chỉ dùng cho test harness; production chỉ một secretRef.
- Firmware test-local dùng board profile đã được gắn với board đang cắm; không ghi
  Wi-Fi/password vào source hay commit. Flash không erase NVS.
- Không đổi kết nối mạng máy tính; Tailscale chỉ dùng `serve` private sau khi user
  cài/enable.

## Evidence — host/config gate

Đã chạy trên Ubuntu host (không đổi interface/Wi-Fi):

- `veetee-server/.venv/bin/pytest -q`: **7 passed** (golden v1/v2/v3 framing,
  pipeline fixture, WebSocket v3 handshake/turn).
- `npm run build` và `npm test` trong `veetee-manager-api`: **2 tests passed**;
  `npm run typecheck`, lint, unit test và build của Manager Web: **12 unit tests
  passed**.
- `python3 -m pytest -q tools/runtime`: **3 passed** (dependency order, cycle và
  shell operator rejection).
- Host-native supervisor manifest đã start + readiness-check đồng thời:
  `veetee-manager-api` (HTTP 18001), `veetee-server` (HTTP/WS 18000) và
  `manager-web-preview` (HTTP 18081). Các port này là override trong manifest để
  không đụng service đang chạy ở port mặc định của workspace khác.
- API runtime snapshot trả revision/ETag; publish role mới được đọc lại qua
  `/internal/v1/runtime-config` mà không restart process trong test injection.
- Test-only Groq probe đã đọc 4 key từ owner-only file (không in key): cả 4 trả
  model list HTTP 200 với 15 model. Probe streaming trên các candidate cho thấy
  `llama-3.3-70b-versatile` có first text khoảng 300 ms và tool-call delta trong
  lần đo này; `llama-3.1-8b-instant` khoảng 422 ms và cũng có tool-call delta.
  Đây là measurement một lần, không tự biến thành model hard-code; model ID vẫn
  phải được chọn/publish trong Web theo revision và benchmark lặp lại.

Các số trên là contract/fixture evidence, chưa phải physical speaker acceptance
hoặc warm TTFA benchmark. Raw credential và Wi-Fi secret tuyệt đối không ghi ở
đây; transcript dưới đây chỉ là câu trong audio sample package, không phải dữ
liệu người dùng.

## Evidence — real provider path

Đã cài optional packages trong `veetee-server/.venv` và chạy một process fixture
tạm thời trên port 18102, không thay process runtime chính của workspace:

- `faster-whisper==1.2.1`, CTranslate2 CUDA và CUDA 12 runtime wheels.
- PhoWhisper-small CTranslate2 local artifact, `device=cuda`, `float16`, 4 CPU
  threads: load khoảng 2,4 s; nhận dạng audio sample 2,64 s trong khoảng 3,8 s
  từ lúc khởi tạo adapter; output tiếng Việt không rỗng.
- VieNeu `3.2.4`, `v3turbo`, ONNX/int8, output native 48 kHz được resample 24 kHz.
  Model lazy-load ở lần TTS đầu; process không tăng VRAM đáng kể sau ASR.
- Groq capability probe với 4 test key: 4/4 HTTP 200, không key nào rate-limit.
  Real-turn test chỉ dùng một key ephemeral, không rotate key trong provider.
- Resolver integration dùng encrypted AES-256-GCM entry và một `secretRef` opaque
  đã gọi Groq thành công; response không chứa key. Runtime fallback file cũ chỉ
  còn cho fixture/test harness và vẫn yêu cầu đúng một dòng key.
- Synthetic WebSocket v3 với audio sample: 44 frame uplink, events
  `hello → stt → tts:start → sentence_start ×3 → tts:stop`, 145 frame Opus
  downlink, elapsed khoảng 19,1 s (bao gồm cold-load TTS và network). Đây là
  functional evidence, chưa phải TTFA p95.
- `nvidia-smi` tại thời điểm PhoWhisper warm báo khoảng 705 MiB used / 3.011 MiB
  free trên GTX 1650 Ti; VieNeu ONNX chạy CPU. Cần benchmark warm TTFA và long
  session trước khi promote snapshot thật.

## Limitations / next gate

- Runtime chính ở port 18100 vẫn giữ snapshot fixture để board/network soak không
  phụ thuộc API key. Real provider path đã pass ở process tạm; Manager publication
  của secretRef chưa được dùng cho voice process.
- Firmware đã build/flash không erase NVS. Board vào AP 2.4 GHz, nhận IP
  `192.168.110.237`, WebSocket v3 handshake thành công và server hello được chấp
  nhận. Chưa có bằng chứng người dùng đã nghe speaker hoặc đã nhấn PTT vật lý.
- Firmware host tests: `cmake -S host-tests -B host-tests/build2`, build và
  `ctest --test-dir host-tests/build2`: **1/1 pass** (v3 golden frame, state
  generation/abort và flash safety gate).
- ESP-IDF v6.0.2 target `esp32s3`, `idf.py build` thành công, binary
  `build/veetee-firmware.bin` `0x11d860` bytes; host test `1/1` pass. `idf.py
  flash` chỉ ghi bootloader/partition/app, không chạy `erase_flash`; serial xác
  nhận app `2acfc59-dirty`, Wi-Fi 2.4 GHz, IP và `WebSocket v3 ready`.
- Tailscale không có binary trong shell hiện tại nên tôi không tự cài, `tailscale up`
  hay thay route của máy. Không có claim HTTPS/hostname mới trong evidence M0;
  phần private Serve vẫn theo ADR-012 và cần operator enable rồi kiểm tra từ một
  peer khác trong tailnet.
- Runtime manifest hiện chạy Voice Server ở `config_source=manager` (local
  insecure flag chỉ cho bring-up), vì vậy Manager Web/API là nguồn chỉnh cấu hình
  thật trong phiên chạy. Test đã PATCH role → POST publish qua API (`revision=2`),
  sau đó Voice Server poll ETag nhận HTTP 200 một lần rồi quay về HTTP 304; không
  restart process và không đổi provider âm thầm.
- PostgreSQL adapter và device pairing/MCP hardware thuộc gate tiếp theo; memory
  API hiện dùng host memory khi chạy `VEETEE_DATABASE_MODE=memory`.
