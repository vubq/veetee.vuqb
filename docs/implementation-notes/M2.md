## Device pairing slice (2026-08-04)

- Route `POST /api/v1/devices/pair` không còn trả `501`. Luồng mới gồm machine
  endpoint `POST /internal/v1/devices/pairing-challenges` tạo challenge một lần,
  trả mã `VT-xxxx` đúng một lần; owner nhập mã để bind device vào assistant.
  Code chỉ lưu SHA-256 hash, có expiry 10 phút và trạng thái `pending → used`;
  không lưu raw code hoặc identity hash trong public response.
- Data model PostgreSQL thêm `device` và `pairing_challenge` trong migration
  `003_device_pairing.sql`, với unique `(identity_hash, client_id_hash)`, owner/
  assistant binding và index theo trạng thái/expiry. InMemory store dùng cùng
  semantics để preview/test không lệch production.
- `GET /api/v1/assistants/{id}/devices` trả device card allow-list; response chỉ
  có masked MAC, board, firmware, trạng thái và timestamps. Machine challenge
  request được redact `verificationCode` trong logger policy.
- Test evidence: Manager API **12/12** pass, gồm challenge single-use ở memory
  và PostgreSQL persistence/restart; migration `veetee_manager` chạy thành công.
  OpenAPI/Redocly và Web generated contract cập nhật; Web typecheck/lint/unit
  **12/12** và build pass.
- Đây chưa phải physical pairing acceptance: firmware chưa gọi challenge endpoint
  và voice/MCP device reporting vẫn là gate firmware/hardware tiếp theo.

## Generated HTTP operation client (2026-08-04)

- Manager Web nay dùng `openapi-fetch` với `paths` được sinh từ
  `veetee-manager-api/openapi/manager-api.json`; gateway gọi các operation typed
  (`GET`/`POST`/`PATCH`) với path params, query params, request body và response
  type lấy trực tiếp từ artifact. Các cast `fetch` + `unknown` cho route chính đã
  được loại bỏ; mapping từ API resource sang domain UI chỉ còn ở một boundary.
- Client có middleware session dùng `credentials: include`, tự lấy CSRF token từ
  `/api/v1/auth/me` khi cần và gắn `X-Veetee-CSRF` cho mutation. Login cập nhật
  token trong memory; không ghi credential/token vào `localStorage` hoặc
  `sessionStorage`. Network exception được chuyển thành problem offline hữu hạn,
  không queue mutation vô hạn.
- API bổ sung query contract cho assistant search, voices, provider configs và
  machine runtime config; assistant search filter chạy ở API thay vì nối chuỗi
  query trong Web. Model/memory response schema đã khai báo enum/oneOf để
  generated type bảo toàn provider kind và selected-vs-disabled invariant.
- Regression: API search validation, OpenAPI export/check và client CSRF tests;
  Manager Web typecheck/lint/Vitest **14/14** và production build pass. Đây là
  generated-client contract gate; login UI, rate-limit production và history /
  retention vẫn chưa được promotion.

## Login throttling (2026-08-04)

- Local auth có bounded process-local throttle theo ba bucket: IP, normalized
  identity và cặp IP/identity. Giới hạn `maxAttempts`, cửa sổ, lockout và số bucket
  đều là environment config (`VEETEE_LOGIN_*`), không phải literal trong route.
- Sai credential vẫn trả `401 INVALID_CREDENTIALS` cho tới khi gate đạt ngưỡng;
  sau đó trả `429 LOGIN_THROTTLED` cùng `Retry-After`. Identity không tồn tại và
  identity tồn tại không có response code riêng; Argon2 verify được thực hiện trên
  hash owner khi có cấu hình để giảm timing distinction. Thành công xoá bucket của
  IP/identity; map có eviction để không tăng vô hạn.
- Unit/API tests chứng minh lockout hết hạn, bounded map, IP rotation không né
  được gate, valid login bị chặn trong lockout và OpenAPI có response `429`.
  PostgreSQL session/pairing regression vẫn pass **16/16**.
- Đây mới là baseline single-process protection cho local host; distributed
  throttling hoặc reverse-proxy rate limit chỉ được thêm khi có deployment/ADR
  tương ứng. Login UI, history/retention ingest và idempotency cho mutation vẫn
  là phần M2 chưa promotion.
